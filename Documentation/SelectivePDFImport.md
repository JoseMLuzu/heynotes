# Selective PDF import

Import PDF opens a native Files picker followed by an expanded, app-owned selection sheet. Entire Document is selected initially. Choose Pages exposes thumbnail selection, a page/range field and Clear Selection. Tapping a thumbnail while Entire Document is active switches to a selection containing that single page. Further taps toggle individual pages. The confirmation button reports the exact count and is disabled for empty selections, invalid applied ranges or an active import.

Ranges use one-based numbers separated by commas, such as `1, 3-5, 8`. En/em dashes are accepted as range separators. Apply validates all tokens before replacing the selection. Duplicates are removed and selected pages keep their original document order. Negative, zero, reversed, malformed and out-of-document ranges are rejected. Applying an invalid range retains the previous selection but disables confirmation until the range is corrected, selection is changed manually, or Entire Document is chosen.

## Lifecycle and storage

PDFImportStaging copies the picker result to an app-owned temporary directory using the existing coordinated/security-scoped copy pipeline. PDFKit validation and geometry inspection run on a worker actor. Only a Sendable draft containing immutable metadata, a temporary URL and its storage actor reaches the main actor. Preview images use an independent PDFDocumentService actor with a 4 MiB image cache, one document and 320-pixel thumbnail renders, keeping import previews separate from editor rendering. Thumbnails are loaded lazily and cancellation-aware.

The library is unchanged until confirmation. Closing/cancelling the selection sheet discards only its owned temporary directory and preview cache. Confirmation copies the validated staged file to the new notebook's private source path, creates NotePage metadata for the selected original PDF indices, and saves SwiftData. Titles retain the picked filename rather than the temporary copy's UUID. During copying, cancellation and repeated confirmation are blocked. An error remains recoverable in the selector without silently accepting another selection. The temporary copy is discarded when the sheet closes after success as well as cancellation.

Each notebook stores one intact private source PDF, even for a subset. Only chosen pages are exposed through NotePage objects: pageIndex is contiguous from zero, while pdfPageIndex retains the source's permanent zero-based page position. Ink is still saved independently per NotePage. This avoids rewriting PDF content, preserves source annotations, crop/rotation and text, and requires no schema migration. Export reads the notebook's selected page references, so unselected pages are excluded. Selecting fewer pages reduces the notebook's editable page count, not the size of its preserved backing PDF. A terminated process may leave an unconfirmed copy in the OS temporary area; it never becomes a library notebook. Existing conservative handling of uncommitted permanent copies after a failed metadata transaction is unchanged.

PDFImportSelection owns transient selection/import state independently of SwiftUI. PDFPageSelection parses and validates range/index input. LibraryViewModel.importPDF retains its previous whole-document default for existing callers and additionally validates selected indices against the private copy. No account, network service, PowerPoint importer or persistent absolute path is introduced. Existing PDF security/printing restrictions remain in force. The UI uses public APIs available at the iPadOS 17 deployment target and the existing expanded-sheet policy.

## Validation

PDFSelectiveImportTests covers valid/invalid ranges, first-tap single-page selection, selection changes and failure recovery, repeated-confirmation protection, temporary copy cancellation, source-provider disappearance after staging, invalid selections creating no metadata, selected source-index mapping, source-byte preservation, rotated/cropped dimensions, editable PencilKit ink and exported text/page count/pixels. Native sheet captures verify expanded portrait/landscape layout, actual PDF thumbnails and switching the real segmented control to expose range input. Existing PDF import/export, notebook duplication, protected/corrupt input, library and editor tests remain in the full native suite.

Manual iPad acceptance: import a local PDF, choose one page, choose several nonadjacent pages, apply a range, try an invalid/empty selection, cancel and confirm the library is unchanged, then import and reopen the notebook. Write on a selected rotated or landscape page and export the notebook to check count/orientation/ink. Repeat with Files providers, dark appearance, VoiceOver and a large PDF. This implementation is PDF-only; presentation files must first be exported as PDF.

Changes are packaged in scoped commits; repository publication follows explicit user authorization.
